### Directly confirmed integration mistakes or omissions

1. **Tree audio not triggered live.** The original hit/fall source specifies `chop` variants and `treefall_02/03`. Native `Stage2Audio::play_original_world_sound` has corresponding WAV paths, but live `source/main.cpp` invokes it only for doors. Asset existence is not event implementation.
2. **Tree hits do not reach the original source rule in gameplay.** `source_tree_fall_rules.hpp` and world hitboxes exist, but `source/main.cpp` lacks the live tree-hit executor dispatch for player projectile/melee input. Thus unit-tested wood drops do **not** prove player chopping currently works.
3. **Building visuals are not the full original building interaction chain.** Roof alpha is updated in the main loop, but original ancestor checks, overlapping objects and layer/shadow effects still need parity work.
4. **Door sounds exist, but complete doors are still unverified.** Original door frame selection is used; original obstacle/shadow companion state, collision and exact source guards remain incomplete.
5. **World loot spawning has a concrete blocker.** The existing root source trace distinguishes zombie markers (object 218 categories 9/19) from eligible map-loot markers (category 15), with zero eligible markers observed in fixed-seed tests. Do not invent category-15 markers as a workaround.
6. **Saves cover visual state, not every gameplay state.** A tree's fallen frame is not sufficient to restore its HP, hitbox/collision, items and destruction lifecycle.

### What the audit cannot claim yet

A syntactic event index is **not** a complete interpretation of original Construct semantics: event inheritance, object picking, trigger propagation, numeric ACE commands, RNG order, dynamic function names and sound expressions must still be verified per feature against `c2runtime.js`. The source audit's **3,406** currently unclassified event rows and **70** unclassified audio actions are explicit follow-up coverage work, not a basis to assume those original events are unnecessary. The graphics audit's **119** PNGs without direct frame references also remain to be classified.

An emulator or original-versus-port playthrough is necessary to validate frame timing, sound actually playing, collision, screen ordering, persistence, transitions and device performance. The CI run establishes correct indexing, **not** those gameplay outcomes.

## Required method for all subsequent feature fixes

For each event chain: (1) use the original root event UID **and nested path**, (2) expand all inherited conditions and calls in the audit CSV, (3) interpret exact runtime action/plugin semantics, (4) match original sprite frames/imagepoints, sound file and selection conditions, (5) implement every triggered effect in native gameplay together, (6) test native edge cases plus Azahar, (7) test saving/reload and linked effects, (8) log commit, run and evidence in `IMPLEMENTATION_VERIFICATION_TRACKER.md`. **Task 1: World Interactions remains open** until this process finishes for trees, doors, roofs, collisions, objects and their sounds/rewards.

**Next corrective implementation order:** live tree hit+sound+drop+collision; original house/door child effects, layers and audio; world object HP/collision persistence; then world-interaction verification. Task 2 remains gated until Task 1 has end-to-end evidence.
